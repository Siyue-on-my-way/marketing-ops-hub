# Maitian-Hub 用户指南（Codex × 你 · 一份手册全搞定）

> 版本 v2.0 · 2026-11-27。**一份手册**：既是系统使用说明，也是你和 Codex 的分工执行单。每个业务按「**业务目标 → Codex 提示词 / 你的操作 → 完成标志**」组织——能自动化的步骤直接复制提示词给 Codex，必须人做的写清了怎么操作，做完用「完成标志」自查。
> 术语：【Codex】= 你电脑上的 Codex 终端智能体；【你】= 人工；【系统】= hub 自动。**凡涉及扫码、内容确认、点发布、approve 的都是人的活**——这是系统红线，不是分工偏好。

## 目标 1：把这台电脑装成「能干活的驾驶舱」（每台电脑一次，约 30 分钟）

**业务目标**：你的电脑上跑起本地中控（hub）——连着云端素材库、装着 AI 技能、能驱动 ego 浏览器替你操作各平台页面。装完这台电脑就"上岗"。

### 你做（3 件 Codex 替代不了的事）

| # | 怎么操作 |
| --- | --- |
| 1 | 浏览器打开 `http://8.148.26.166:2680/` → 注册（**邮箱或手机号** + 密码 ≥8 位输两遍）→ 登录。注册即创建你的 workspace（你是拥有者）。进顶部「**密钥管理**」页，**复制默认密钥**暂存（随时可回来点「复制」取回；默认密钥不可吊销，新建的可随时吊销） |
| 2 | 到 Citro Labs 官网下载并安装 **ego lite**——替你操作平台页面的 AI 浏览器，**必须亲手装**（任何 LLM 不得代装） |
| 3 | 决定是否让 Codex 代装 Node/Python：同意就在提示词 A 开头加"已授权你安装 Node.js ≥22.5 与 Python 3" |

### Codex 提示词 A（代码与环境）

```text

1. 检查 node -v（需 ≥22.5）与 python3 --version；不满足且我已授权安装，就用本机包管理器装（macOS 用 brew，Windows 用 winget），装完复验。
2. 克隆代码：git clone git@github.com:Siyue-on-my-way/marketing-ops-hub.git ~/marketing-ops-hub（失败改用 https://github.com/Siyue-on-my-way/marketing-ops-hub.git）。
3. 安装技能：mkdir -p ~/.claude/skills && cp -r ~/marketing-ops-hub/content-hub ~/.claude/skills/content-hub。
4. 写配置：复制 ~/marketing-ops-hub/backend/config/config.example.json 为同目录 config.json，把 cloud.base_url 改为 http://8.148.26.166:2680，其余不动。
验证：node -v、python3 --version、ls ~/marketing-ops-hub/backend/src/hub.mjs、config.json 里的 base_url。
汇报：逐项列 结果/缺失项。缺什么就停在那一步说明，不要跳步。
```

### ⏸ 交接点

把门户复制的**默认密钥**粘贴给 Codex，然后发提示词 B。

### Codex 提示词 B（云入职 + 启动 + 自检）

```text
任务：云入职并启动中控（代码在 ~/marketing-ops-hub/backend）。
1. 云入职：node src/hub.mjs join <我粘贴的密钥>。验证输出 ok:true 且 tenant_name 是我的租户名；密钥只能进 backend/data/credentials.json，不得出现在你输出的任何其他地方。
2. 启动中控（长驻进程）：先 curl -s http://127.0.0.1:8787/api/health，未运行则 nohup node src/hub.mjs serve > ~/maitian-hub.log 2>&1 & ，10 秒后复验 /api/health 返回 ok:true。
3. 自检：cd ~/marketing-ops-hub && python3 content-hub/scripts/doctor，输出完整 JSON。
4. 顺手验证凭证通道：node src/hub.mjs whoami 应返回我的用户/租户/密钥名。
汇报：doctor 的 ready 值 + whoami 租户名 + actions[] 剩余缺项。ready:false 时逐条解释缺什么、哪些需要我做。
```

### 完成标志

doctor `"ready": true`，`cloud.whoami` 显示你的租户，`hub whoami` 能查到档案。常见红项只有 ego 未装——回到你的操作清单第 2 条。**这个 serve 终端保持运行**（关机重开后让 Codex 重跑提示词 B 第 2 步即可，登录态不丢）。

## 目标 2：让系统接管一个平台账号（每账号 10 分钟）

**业务目标**：系统获得该账号的操作位（独立 ego 浏览器空间 + 登录态），从此可替它填表、互动、收数据。一个账号只绑一台电脑。
**业务规则**：每平台 ≤5 个号；扫码永远你亲手做；新号自动 14 天冷启动（不发布、互动减半），老号录入时声明 `--mature` 跳过。

### 你做

1. 告诉 Codex：平台、账号昵称、**老号还是新号**、发布模式（**review**=默认，系统填好表单你亲手点发布；**auto**=系统自动发布回读，你不必守电脑。两种模式内容都先经你过目）。
2. ⏸ Codex 弹出浏览器后：**手机打开对应平台 App 扫码**。系统自动快照核对昵称，不符会立即停下（通常是录入昵称写错了）。

### Codex 提示词（以 B 站老号 + review 为例，按实际替换尖括号内容）

```text
任务：接入我的平台账号。参数：平台 bili，昵称 "<昵称>"，老号（--mature），发布模式 review（不开 --auto-publish）。
1. 录入：cd ~/marketing-ops-hub/backend && node src/hub.mjs accounts add bili "<昵称>" --mature，记下返回的 account id。
2. 登录：node src/hub.mjs accounts login <account_id>。它会弹出 ego 浏览器窗口——这时停下来告诉我"请扫码"，命令最多等 10 分钟。
3. 命令返回后核实：快照 displayName 与录入昵称一致、login.ok=true；再跑 node src/hub.mjs accounts list 给我看该账号的 id/platform/status/login。
异常处理：超时未扫码/昵称不符 → 如实报告并停，登录重试不超过 1 次。
```

（要 auto 模式：add 时加 `--auto-publish`，或之后随时 `node src/hub.mjs accounts set <id> --auto-publish on`，关掉用 `off`。）

### 完成标志

`accounts list` 里该账号 `login.ok = true`，昵称与你手机上看到的一致。**换电脑** = 新电脑重新录入 + 扫码，旧电脑不再操作该账号。

## 目标 3：把素材放进云端素材库（发帖的前置）

**业务目标**：视频/图片/文案进入 workspace 共享素材库（同事可见），打上平台标签供"发一条"选用。素材生产仍在你自己的流程完成，系统只管存和发。

### 你做（最省事的一条路）

门户 `http://8.148.26.166:2680/` →「素材库」→ 上传面板**点选/拖入文件**（可多选，单个 ≤500MB）→ 勾平台标签（common=全平台）→「开始上传」。传完可在同一页编辑标题/标签/备注、下载、删除、释放占用。到这就不用 Codex。

### Codex 提示词（批量/命令行场景才需要）

```text
任务：把素材上传到云端素材库。文件：<逐个列绝对路径>；平台标签：<common 或指定 xhs/douyin/tiktok/yt/bili/x/xianyu 组合>；备注：<可选>。
用已存凭证走 API（key 在 backend/data/credentials.json，读出来用但不要打印）：
curl -s -X POST http://8.148.26.166:2680/v1/materials -H "Authorization: Bearer <key>" -F file=@<路径> -F 'meta={"title":"<标题>","type":"<video|image|text>","platform_tags":["common"]}'
验证每个文件返回 id+status:ready；返回 dedup:true 说明与库内重复（sha256 相同），如实报告。
最后跑 node src/hub.mjs materials --limit 10（或 GET /v1/materials）列出最新素材给我核对。
```

### 完成标志

门户「素材库」能看到这些素材（标题/类型/标签/大小），可查看/下载；`hub materials` 也能列出。

## 目标 4：把一条素材发到多个平台（核心业务）

**业务目标**：一条素材以各平台适配的文案（标题/正文/标签逐平台改写）发布出去，URL 归档，第 1/3/7 天自动收数据。
**前提**：目标账号完成目标 2（`login.ok`）且不在冷启动期（冷启动号不能发）。

### 你做（两处，不能省）

1. ⏸ **过目差异表并确认**——Codex 把各平台改写文案列给你，你说"确认"才继续；不满意让它改。
2. ⏸ review 账号：填完后**打开平台页面亲手点「发布」**，再开本机大屏 `http://127.0.0.1:8787` →「待审队列」点「**已发布，回读确认**」。（auto 账号无需此步）

### Codex 提示词

```text
任务：按 content-hub 的「发一条」流程把一条素材发到多平台。
素材：<标题或 id>；平台与账号：<如 xhs+账号a、bili+账号b>；时间：<如 今晚 20:00，留空=最近的活跃时段>。
1. cd ~/marketing-ops-hub && python3 content-hub/scripts/doctor —— ready 不为 true 先停下报告。
2. node src/hub.mjs accounts list —— 核对目标账号 login.ok=true 且不在冷启动（cold 不能发）。
3. node src/hub.mjs materials --platform <平台> 拉素材候选（也可 GET /v1/materials，key 在 backend/data/credentials.json），确定用哪条后 claim 占用锁（30 分钟）。
4. 按平台改写文案（标题/正文/标签逐平台适配：小红书标题≤20字、X≤280字符、TikTok≤2200……），生成差异表。
5. ⏸ 把差异表完整贴给我，等我回复"确认"。未确认前不得排期。
6. 我确认后：写 payload 文件 → node src/hub.mjs plan <material_id> --platforms <...> --accounts <...> [--at "<时间>"] --payload-file <文件>。
7. node src/hub.mjs run --due 触发执行（或说明 serve 守护进程会到点自动执行）。
8. review 账号：执行完提醒我"去平台点发布，然后在大屏点已发布回读确认"，并给我 post_id；auto 账号：说明系统会自动发布回读，把 post_id 和结果给我。
9. 验证：大屏 http://127.0.0.1:8787 的 /api/state 里该帖状态（filled→confirmed）与发布 URL。
任何一步失败：报告 ①状态②已试③下一步建议，重试不超过 2 次。
```

### 完成标志

大屏该帖 `confirmed` + 发布 URL；平台后台可见内容。回读未通过 = 平台审核中，稍后在大屏再点一次「已发布，回读确认」。

## 目标 5：养号——点赞/评论/话题互动

**业务目标**：账号保持真实活跃（像人在互动，不是刷量），trust_score 随无风控天数上涨、配额逐步放开。
**业务规则**：一切互动必须 **AI 草拟 → 你 approve → 才执行**；评论必须引用对方内容、禁止模板；间隔 30–120 秒随机；活跃时段 9–21 点。

### 你做

⏸ 本机大屏 `http://127.0.0.1:8787` →「待审队列」→「互动待审」：逐条看草拟，点 **approve** / **reject**（都看过也可"批准今日全部"）。执行、间隔、截图都是系统的活。

### Codex 提示词（私聊把首行换成"私聊好友"并说明对象与意图）

```text
任务：按 content-hub 的「养号巡检」流程给账号 <account_id> 做今日互动。话题/目标页：<链接，留空则让我先给>。
1. node src/hub.mjs health —— 确认该号登录正常、互动配额有余量（余量=上限×trust_score，冷启动减半）。
2. 采集目标：按给定话题/列表页取快照选目标，同账号同目标去重。
3. 逐条草拟：评论必须引用对方内容、个性化，禁止模板（同批相同草拟 ≥3 条 hub 会直接拒绝）；点赞只对已浏览内容。
4. 把草拟清单汇总贴给我，提醒我去大屏 approve；approve 后 hub 按 30–120 秒拟人间隔自动执行，你不用代执行。
5. 验证：node src/hub.mjs health 里配额用量上升；异常（skipped(risk) 等）如实报告。
```

### 完成标志

大屏「审计时间线」出现 executed 记录；健康页配额用量上涨、trust_score 上行。

## 目标 7：看账号今天能不能用（健康检查）——全自动托付

**业务目标**：一眼看清每个账号的可用性：登录态、今日配额余量、trust_score、风控事件。

### Codex 提示词

```text
任务：跑 node src/hub.mjs health，用中文表格汇总每个账号的 登录态/trust_score/今日各配额上限与已用/风控事件。最后给结论：今天哪些号能发、哪些只能互动、哪些停机（及原因）。
```

（自己看：大屏 `http://127.0.0.1:8787` →「账号健康」。）

**怎么读**：配额上限（trust=1 时）发 ≤2 / 赞 ≤30 / 评 ≤5 / 私信 ≤10 每天；**实际余量 = 上限 × trust_score**；新号冷启动再减半且不能发，连续无风控每天 +0.05、满 0.8 且满 14 天自动转正；风控命中当日清零，累计 3 次进 `banned_watch` 需人工。

### 完成标志

拿到"今天哪些号能干嘛"的结论，直接决定目标 4/5/6 用哪些号。

## 目标 8：复盘已发帖子的效果——全自动托付

**业务目标**：知道每条帖子第 1/3/7 天的表现，以及**和你自己上期同龄帖**（发布后同一天）相比的进退，指导下期选题和文案。

### Codex 提示词

任务：跑 node src/hub.mjs review <post_id> [天数，默认7]，用中文解读复盘卡片：各天数据、与自己上期同龄帖的差值意味着什么、下期选题/文案的 2-3 条具体建议。post_id 我没给就先从大屏 /api/state 或审计里查。

（数据采集是自动的：发布后第 1/3/7 天系统自动进创作者后台读数，无需你操作。）

### 完成标志

拿到复盘卡片与解读；数字与平台后台一致（抽查 1 个即可）。助手据此产出的"进化提案"需你在大屏「进化提案」approve 后才生效。

## 目标 9：和同事共用团队空间

**业务目标**：多人多台电脑共用一个 workspace：共享素材库与台账；账号不重叠（一个账号只在一台电脑）。

### 你做

1. 门户顶部「**邀请**」页 → 生成邀请链接 → 发给同事。
2. 同事打开链接注册（自动加入你的 workspace，成为成员，自带一把自己的密钥）。

### 交给同事

把本手册发给同事：按**目标 1**（开场白 + 提示词 A/B，用它自己的默认密钥 join）和**目标 2**接入**不与你重叠**的账号。拥有者可在门户「成员」页移除成员（其密钥立即失效）。

### 完成标志

门户「成员」页看到同事；素材库互相可见。

## 附录 B：排障（现象 → 处理）

| 现象 | 处理 |
| --- | --- |
| doctor 某项红 | 按 `actions[]` 提示补；不行把整段 JSON 发管理员 |
| `skipped(no_login)` | 登录态失效：重做目标 2 的扫码登录 |
| `skipped(quota)` | 当日配额用完，明天再试或换号（先做目标 7 看余量） |
| 风控停机 | 看大屏审计里的截图，次日自动恢复；连续 3 次进 `banned_watch` 需人工 |
| `duplicate` | 同素材同账号同平台防重命中，换素材 |
| 素材一直"被占用" | 占用锁 30 分钟自动释放；急用就在门户「素材库」打开该素材点「**释放占用**」 |
| 回读未通过 | 平台审核中，稍后在大屏再点一次「已发布，回读确认」 |
| 云 401 | 凭证被吊销/过期：门户「密钥管理」拿新 key，重新 join |
| 大屏空白/要 token | 本机大屏随 `hub serve` 启动；带 SERVER_TOKEN 的入口是运营大屏（管理员用） |

**纪律（系统强制）**：发布内容永远先经你过目（差异表）；互动 approve 后才执行；新号 14 天冷启动；验证码/风控即停绝不绕过；只管自有/公司账号（每平台 ≤5），批量注册、模拟人设、群控会被拒绝。

**路线提示**：未支持的场景到父 issue 提需求；疑似 bug 附上 `doctor` 的 JSON 输出。
